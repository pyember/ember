# Ember v0.2 design

Status: accepted, implementation in progress on the `v0.2` branch.

Ember v0.2 is a rewrite. The v0.1 tree on `main` stays readable in git history for reference, but no
v0.1 module is carried over unless this document names it. The audit that motivated the rewrite found
126 distinct defects, 36 of them severe; most trace back to a few habits this design removes by
construction: globals used as dependencies, behaviour inferred by heuristics instead of declared,
several copies of one table or wire format, claims with no measurement, failures reported as success,
resources with no owner, and a library doing an application's work at import time.

## Goals

- Calling a model is one line, and every call reports exactly what happened: text, tool calls, a
  finish reason, token usage split by kind, cost when the price is known, and the provider request id.
- Independent model calls overlap automatically inside `@xcs.jit`, with no change to what the program
  computes. Section "xcs" states the guarantees.
- Compositions (ensembles, judges, votes, verifiers) are plain typed objects, and the NON notation
  compiles to them and runs.
- `import ember` performs no I/O, starts no threads, and cannot fail because of a config file.
- Every public example in the README runs in CI against a fake provider.

## Non-goals for v0.2

- Automatic differentiation or JAX integration. JAX users call JAX directly.
- Bedrock and Vertex adapters. OpenAI-compatible endpoints (Azure v1, Ollama, vLLM, any gateway) are
  covered by one adapter.
- Request deduplication or provider batch APIs. Deduplication would break sampling at temperature > 0.
- Live model discovery. The catalog is data in the repository; unknown models still work (below).
- Gemini's Interactions API. Google now recommends it as the default and calls `generateContent`
  legacy but supported; v0.2 ships a `generateContent` codec because it is stateless per request
  like every other codec here. An Interactions codec is the first follow-up for Gemini.

## Layout

Folders follow features, and dependencies point one way:

```
ember/errors.py      one error type for model calls, a few for config and usage
ember/context.py     immutable configuration, one contextvar, override layers
ember/config.py      the config file: one reader, one atomic writer, redaction
ember/xcs/           the concurrency runtime: scheduler, jit, map, recorded graphs
ember/llm/           model calls: catalog, request/result types, client, providers
ember/operators/     Operator, Chain, Ensemble, Judge, Vote, Verify, @op
ember/non/           the NON grammar and its compiler to operators
ember/data/          dataset streaming (optional extra)
ember/eval/          evaluation runs that record every request's outcome
ember/cli/           `ember` command
```

Allowed imports: `errors` <- `context`, `config` <- `xcs` <- `llm` <- `operators` <- `non`; `data` and
`eval` may use `llm`, `operators` and `xcs`; `cli` may use anything. Nothing imports `cli`. A test
enforces this table.

## Dependencies

Core: `httpx`, `pydantic`, `pyyaml`, `greenlet`. Ember speaks each provider's HTTP API directly through
its own codecs, so no provider SDK is required. Extras: `data` (`datasets`, `huggingface-hub`), `dev`.
No exact pins and no upper caps without a written reason next to the pin.

## Errors

`ember.errors` defines:

- `EmberError(Exception)`: base of everything ember raises on purpose.
- `ConfigError(EmberError)`: unreadable or invalid configuration, missing credentials.
- `ModelError(EmberError)`: any failed model call. Fields: `kind: ErrorKind`, `provider: str`,
  `model: str`, `status: int | None`, `request_id: str | None`, `retry_after_s: float | None`. The
  message is built from these fields and a short reason string; it never embeds upstream response
  bodies, file paths or credentials.
- `ErrorKind` (closed enum): `AUTH`, `PERMISSION`, `NOT_FOUND`, `BAD_REQUEST`, `RATE_LIMITED`,
  `OVERLOADED`, `SERVER`, `TRANSPORT`, `UNPRICED`, `CANCELLED`. `ModelError.retryable` is derived from the
  kind: `RATE_LIMITED`, `OVERLOADED`, `SERVER`, and `TRANSPORT` before the first response byte.
- `NonSyntaxError(EmberError, ValueError)`: invalid NON specification, with the column of the error.

Truncation, refusals and content filtering are not errors: they are finish reasons on the result.

## Context and configuration

- One `contextvars.ContextVar[Context]`. No thread-locals, no module globals holding state.
- `Context` is immutable. `ember.context.current()` returns the active one; the first call builds the
  root from the config file, which is the first moment ember reads disk.
- `with ember.context.override(...)` pushes an immutable layer and restores the previous context with
  the token it received, so nested and concurrent use is safe. Overrides are never written to disk.
- Credentials resolve in this order: an override, the provider's standard environment variable
  (`OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GEMINI_API_KEY`, or the one named in that provider's config),
  then the config file. A missing credential raises `ConfigError` naming the variable to set. Ember never
  prompts, never launches a setup program, and never writes a key it was not explicitly asked to save.
- Every task ember runs on another thread or greenlet runs inside a copy of the caller's context.
- `ember.config` owns `~/.ember/config.yaml` (or `EMBER_CONFIG`): one reader, one atomic writer with
  mode 0600, and one redacting serializer used by every CLI path that prints configuration.

## Models (`ember.llm`)

### Names and the catalog

- A model is named `provider/name`, for example `openai/gpt-5` or `anthropic/claude-sonnet-4-5`. The
  string is parsed once into `ModelRef(provider, name)` at the API boundary and never re-split.
- The catalog is one data file, `ember/llm/catalog.toml`, loaded once into an immutable `Catalog`. Each
  entry (`ModelSpec`) holds the provider, the wire id sent to the API, aliases, context window, maximum
  output, which wire API it uses, the allowed reasoning efforts, which sampling parameters it accepts,
  and its rates. Every rate carries the URL of the provider's published price page and the date it was
  read.
- Resolution: an exact catalog id or alias resolves to its spec. A `provider/name` that is not in the
  catalog still works when the provider is known: the name is sent as the wire id and the spec is
  marked unknown, so the context window and price are unknown. A bare name that is not an alias raises
  `ModelError(NOT_FOUND)` before any request is sent. No prefix guessing and no network discovery.

### Requests

`Request` is a frozen dataclass: `messages: tuple[Message, ...]`, `system: str | None`,
`tools: tuple[ToolSpec, ...]`, `tool_choice`, `sampling: Sampling`, `output_schema`, and
`extensions: Mapping[str, object]` for provider-specific fields that the caller names explicitly.
`Message` has a role and a tuple of typed parts (`TextPart`, `ImagePart`, `ToolCallPart`,
`ToolResultPart`). Invalid combinations raise when the request is constructed, before anything is sent.
The public call accepts these fields as explicit keyword arguments; there is no `**kwargs` bag.

### Results

`Result` is a frozen dataclass: `text`, `tool_calls`, `finish_reason: FinishReason` (closed enum:
`STOP`, `LENGTH`, `TOOL_CALLS`, `CONTENT_FILTER`, `REFUSAL`), `usage: Usage`, `cost: Money | None`,
`model: ModelRef`, `request_id: str | None`, `latency_s: float`.

`Usage` splits tokens into `input` (uncached), `cache_read`, `cache_write`, `output` (including
reasoning) and `reasoning` (the part of `output` spent reasoning), plus `measured: bool`. Ember never
estimates token counts; a provider that reports none yields `measured=False` and zeros.

`Money` is an integer number of nano-dollars, so three tokens at $0.15 per million cost 450, not
zero. Cost is computed once per call from the spec's rates, exactly, with one final rounding. When the provider reports its own cost, that figure wins. When the
model has no known rate, `cost` is `None`; a context option `require_price=True` turns that into a
`ModelError(UNPRICED)` raised before the request is sent.

### Calls and pending results

The public call, exported as `ember.models`:

```python
models(
    model: str | ModelRef | None,          # None uses the context's default_model
    prompt: str | Sequence[Message],
    *,
    system: str | None = None,
    tools: Sequence[ToolSpec] = (),
    tool_choice: ToolChoice = "auto",
    temperature: float | None = None,
    top_p: float | None = None,
    max_output_tokens: int | None = None,
    stop: Sequence[str] = (),
    seed: int | None = None,
    reasoning_effort: str | None = None,
    output_schema: Mapping[str, JsonValue] | None = None,
    extensions: Mapping[str, JsonValue] | None = None,
) -> Completion

models.stream(...same arguments...) -> Iterator[Event]
models.bind(model, **same keyword defaults) -> BoundModel   # a callable taking the prompt
```

A model string is either `provider/name` or a catalog alias such as `gpt-5`. Settings a model does
not accept (for example `temperature` on a model that rejects it) raise `ValueError` before sending.
`ember.llm.Client` exposes the same calls for callers who construct their own client and
provider factory instead of using the context's default.


`ember.models(model, prompt, ...)` returns a `Completion`. A `Completion` is a `Result` that may still
be in flight: the request has already been built from the call-site arguments and sent, and reading any
field waits for it. Outside `@xcs.jit` the call waits before returning, so it behaves like a plain
synchronous call. Inside `@xcs.jit` it returns at once (section "xcs").

`ember.models.stream(...)` yields typed events: `TextDelta`, `ReasoningDelta`, `ToolCallDelta`,
`UsageEvent`, and a final `Done(result)`. Text and tool calls never share a channel.

### Providers

A provider is a codec plus a transport. The codec is pure: `encode(spec, request) -> body`,
`decode(body) -> Result`, and `decode_events(sse_events) -> Iterator[Event]`. It is tested against
recorded wire traffic. The transport owns one long-lived `httpx.Client` per provider configuration,
adds authentication, and maps HTTP failures to `ModelError` kinds. Adapters never retry.

Shipped codecs: OpenAI Chat Completions, OpenAI Responses, Anthropic Messages, Gemini
`generateContent`. Shipped providers: `openai`, `anthropic`, `gemini`, and `openai_compatible`, which is
OpenAI Chat Completions at a configured base URL under a provider name the user picks.

Timeouts are connect and idle bounds (no byte for N seconds), never a cap on total generation time.

### The client

`Client` resolves a `ModelRef` against the catalog, checks price policy, acquires capacity from the
provider's limiter, sends, and builds the `Result`. It is the only place that retries: it retries
`ModelError`s whose kind is retryable, at most a configured number of times, with jittered backoff
that honours `retry_after_s`, and never after the first response byte of a stream. The limiter is
additive-increase/multiplicative-decrease, grows only while saturated, and hands out single-use
permits.

### How model calls meet the scheduler

`ember.llm` reaches the scheduler only through `ember.xcs.runtime`:

- The client acquires a rate-limit permit before sending. `Limiter.acquire(provider)` returns a
  future that completes when capacity is free, and the client reads it with `runtime.wait`, so a
  call waiting for capacity lets other greenlets run.
- The client then hands the request to `runtime.dispatch` (or `runtime.dispatch_stream` for
  streaming). Worker threads therefore only run requests that already hold a permit, and they never
  wait on other ember work. A provider at its limit cannot block requests to other providers.
- Every result, including a permit, is read through `runtime.wait`.
- `runtime.deferred()` says whether the caller is inside `@xcs.jit` or `xcs.map`. Outside, a model
  call waits for its result before returning and raises its error at the call site. Inside, it
  returns a pending `Completion` and the error raises on first read, or at the jit boundary if
  never read. The rule depends only on scope, never on whether a request happened to finish
  before `dispatch` returned. Errors found before sending (an unknown model, a setting the model
  does not accept, an unpriced model under `require_price`) raise at the call site in both cases.
- Retries run inside the dispatched task, which holds its permit through backoff. The worker
  pool must therefore never be a tighter bound than the permits: a provider backing off must not
  delay requests to another provider.

### Observing attempts

`ember.llm.observe.observing(observer)` installs an observer for a block. The client reports every
attempt of every call made in that block, retries included, as an `Attempt` (call id, attempt number,
model, latency, the `Result` or `ModelError`, and whether it will retry). `ember.eval` builds its
per-request records on this; nothing else needs a callback.

## xcs

### `@xcs.jit`

Decorating a function with `@xcs.jit` changes when model calls wait, never what the function computes.

Inside a jit call, every model call builds its request from the arguments as they are at the call
site, sends it immediately, and returns a pending `Completion`. The function keeps running. Reading a
field of a pending `Completion` waits for that call only. Python runs the function exactly once, in
program order; only network waits overlap. Independent calls written one after another therefore run
concurrently, and a step that reads earlier results waits for exactly those results.

Guarantees, each covered by a test:

- Each model request and each user function body runs exactly once per call.
- A request is built from the values its arguments had at the call site.
- No value is read before it is complete, and nothing is cached across calls.
- Within one jit call, user code never runs in parallel with other user code. Functions started by
  `xcs.map` interleave only at points where one of them reads a pending result.
- An error is raised with its original type when the failed value is first read, or when the jit call
  returns if it was never read. Every pending call created inside a jit call has finished before it
  returns.
- The context active at a call site is the context its request uses.
- At most a configured number of requests are in flight per provider; beyond that, the call that
  would exceed it waits.

### The graph

Each jit call records the graph it executed: nodes are model calls and operator invocations, and an
edge means a request was built after its greenlet read the other node's result. The recorded graph is
cached per function and serves only as a plan: when requests compete for limited capacity, those with
the longest predicted remaining path go first, and `jit(f).graph()` shows nodes, edges, timings and the
critical path of the last run. A run that departs from the plan drops it for that run. The graph is never
replayed in place of running the function, and no request is sent before the program reaches it.

Operators and NON graphs declare their structure, so `jit` compiles them ahead of execution and can
plan the whole graph before the first request: critical-path order under rate limits, and token and
cost bounds from the catalog, labelled as bounds.

### `xcs.map`

`xcs.map(fn, items)` runs `fn` on each item concurrently and returns the results in order. Each item
runs in its own greenlet on the caller's thread with a copy of the caller's context; only network I/O
uses worker threads, and worker threads never wait on other work, so nesting cannot deadlock. If an item
raises, no further items start, in-flight items finish, and the first error by item order is raised.

The scheduler uses `greenlet`, which is a core dependency.

## Operators

An operator is a frozen, slotted dataclass that implements `forward(self, input: In) -> Out`, typed as
`Operator[In, Out]`. `dataclasses.replace` is the only way to change one. Validation is optional and
declared in one place: `input_model` and `output_model` class attributes holding pydantic models with
`extra="forbid"`, checked at the call boundary. Nothing is inferred from parameter names or annotations.

Built-ins: `ModelCall` (prompt template plus model), `Chain`, `Ensemble`, `Judge`, `MajorityVote`,
`Verifier`. `Ensemble(members, quorum=..., deadline_s=...)` runs members through `xcs.map` and returns
each member's outcome. An empty ensemble cannot be constructed. `@op` turns a function into a
`FunctionOperator` at decoration time.

## NON

One grammar, parsed by a tokenizer, no legacy form:

```
graph  := stage ("," stage)*
stage  := count TYPE "@" model params?      for E, J, V
        | count "M"                          majority vote, no model
model  := provider "/" name                  name may contain ":" "." "-" "_"
params := "(" key "=" value ("," key "=" value)* ")"
```

`TYPE` is `E` (ensemble), `J` (judge), `M` (majority vote) or `V` (verifier); counts are at least 1;
parameter values are typed by the stage's schema and duplicate keys are errors. `build_graph(spec)`
returns an `Operator` that runs.

## Data and eval

`ember.data.stream(name, split=..., limit=...)` streams a dataset through the `data` extra.
`ember.eval` runs an operator over a dataset and records, for every request, the outcome, retries,
latency and request id, so a run can be reconstructed from its records alone.

## Testing

- Unit tests run with no network: providers are exercised through recorded wire fixtures and a fake
  transport.
- The xcs oracle: for every program in `tests/oracle/`, `jit(f)(x) == f(x)`, the multiset of provider
  requests is identical, the side-effect log is identical (program order) for jit and per-item order
  for `map`, and wall time with independent calls is at most the plain run's. Oracle programs live in a
  module whose name matches nothing ember treats specially.
- Every README code block runs as a doctest against the fake provider.
- An import test asserts that `import ember` succeeds with an unreadable config file, starts no
  threads, and imports no provider or data dependency.

## CI

One workflow on `runs-on: ${{ vars.CI_RUNNER || 'ubuntu-latest' }}`: `ruff check`, `ruff format
--check`, `mypy --strict src`, tests on Python 3.11 and 3.13, `uv lock --check`, and a job that builds
the wheel, installs it into a clean environment and imports ember.

## Removed in v0.2

The frame tracer and everything built on it (IR builder, graph analysis, parallelism estimator, replay
engine, capacity broker, profiler), the JAX operator base and `LearnableRouter`, `ValidationHelpers`,
the setup wizard and launcher, the pricing updater, the pyasn1 import hook, config migrations and the
compatibility adapter, both logging modules, the capabilities table, `DataRegistry` and the dataset
entry points, `integrations/`, and every re-export shim.
